# Modeling Human Activity States Using Hidden Markov Models

A Hidden Markov Model, built from scratch in NumPy, that recognizes four activities (**standing, walking, jumping and still**) from smartphone accelerometer and gyroscope data. On two unseen test sessions it reached **94.4% accuracy (119/126 windows)**, and every error fell within about 2 s of an activity change.

**Use case:** an *active-break coach* for students. The phone notices long sedentary periods (phone lying still on the desk) and checks whether a movement break (standing, walking, jumping) actually happened.

## Dataset

|  |  |
|---|---|
| Device | Huawei P20 (EML-L09), Android 9 |
| App | Sensor Logger 1.68 |
| Sensors | Accelerometer (linear acceleration), Gyroscope, Gravity |
| Sampling rate | Configured 100 Hz, measured ≈98.0 Hz, resampled to exactly 100 Hz |
| Training data | 52 clips: 13 × standing, walking, jumping, still; 10 s each (130 s per activity) |
| Test data | 2 continuous sessions (≈65 s each), walking → standing → jumping → still |

**Phone position:** upright in portrait at belt level for standing, walking and jumping; flat on a table, screen up, for still.

**File naming:** `data/train/<activity>_<NN>.csv`, e.g. `walking_07.csv`. Test sessions are `data/test/test_01.csv` and `test_02.csv`, with labels in `test_0X_labels.csv` (`start_s, end_s, activity`, in seconds since recording start, read from the video).

**Columns in every cleaned CSV:**

| Column | Description |
|---|---|
| `timestamp_ns` | Unix timestamp in nanoseconds |
| `seconds` | Time since the start of the clip (s) |
| `acc_x`, `acc_y`, `acc_z` | Linear acceleration, gravity removed (m/s²) |
| `gyro_x`, `gyro_y`, `gyro_z` | Rotation rate (rad/s) |
| `grav_x`, `grav_y`, `grav_z` | Gravity vector, i.e. phone orientation (m/s²) |
| `activity` | Label: standing, walking, jumping or still |

## Method

1. **Pre-processing:** trim the first 2 s and last 1 s of each recording, keep the central 10 s, and resample all sensors onto one even 100 Hz grid.
2. **Windowing:** 2 s windows (200 samples) with 50% overlap, giving one observation per second.
3. **Features (12 per window):**
   - 8 time-domain: magnitude mean/std, SMA, gyroscope mean/std, axis correlation, gravity orientation.
   - 4 frequency-domain from the FFT: dominant frequencies, movement-band energy ratio, spectral entropy.
   - Intensity features are log-transformed, then all features are Z-score normalized using training statistics only.
4. **Model:** a 4-state HMM with diagonal Gaussian emissions, implemented in NumPy in log-space:
   - forward-backward;
   - Baum-Welch with a log-likelihood convergence check (ε = 10⁻⁴);
   - Viterbi decoding.
5. **Training:** supervised initialization from labelled windows, then Baum-Welch refinement on 13 training sessions built from the clips.
6. **Evaluation:** Viterbi decoding of the two unseen sessions, compared with video-based labels.

## How to run

Requires Python 3.10+ (developed on 3.12.7).

```bash
git clone https://github.com/henryparfait/hmm-human-activity-recognition
cd hmm-human-activity-recognition
pip install numpy pandas matplotlib ipykernel
```

Open `hmm_activity_recognition.ipynb` in VS Code or Jupyter and choose **Run All**. The notebook rebuilds the cleaned CSVs from `data/raw/`, extracts the features, tests the HMM on synthetic data, trains it, evaluates it on the test sessions and saves every figure to `figures/`.
